# Compatibilidad de Óxido 0.1 con Rust

Esta matriz describe el **alcance verificado**, no compatibilidad general con Rust ni un techo permanente del lenguaje. El objetivo es interoperar con bibliotecas Rust sin modificar su fuente, según [ADR 0007](adr/0007-contrato-interoperabilidad-rust.md). Rust 2024 es la edición objetivo. La aceptación exige pruebas de fidelidad, casos positivos/negativos y compilación con Cargo/rustc cuando aplique; las brechas de interoperabilidad enumeradas aquí deben cerrarse en la Fase 8; la Fase 10 aporta infraestructura transversal de pruebas y reportes.

| Área | Decisión 0.1 | Estado actual del repositorio |
|---|---|---|
| Funciones libres | Estructura bilingüe en ambos modos; firma preservada como Rust | Parcial: generación y roundtrip de funciones; Cargo/rustc verificado con Hola, mundo |
| Variables y tipos | `dejar`; `mutable` equivale a `mut`; anotación local opcional | Inferencia local estática delegada en rustc y probada E2E; parámetros y firmas siguen las reglas de tipos de Rust. No hay inferencia propia |
| Bloques | `:`+indent o `{}` según modo, nunca mezclados como bloques | Los dos modos se generan; pruebas comparan semántica de bloques y expresiones finales |
| Valor del bloque | Última expresión sin `;` retorna valor; con `;` devuelve `()` | Regla preservada y probada para funciones, controles y métodos |
| `if/else`, `loop`, `while`, `for` | Keywords bilingües y bloques en ambos modos | Verificado para el corpus de funciones y controles; la semántica de expresiones sigue delegada en Rust |
| Tipos, referencias y borrowing | Sintaxis Rust preservada y parseada; semántica a `rustc` | Implementado para tipos y referencias Rust del corpus de funciones; préstamo probado end-to-end |
| Tuplas, arrays y tipos primitivos | Sintaxis Rust preservada; semántica a `rustc` | Implementado y probado en código ejecutado |
| `struct`, `enum`, `impl`, `trait`, `mod`, `use` | Items con sintaxis Rust o estructura indentada documentada | `struct`/`enum`/`use` indentados desde Fase 7; Fase 8 añade `impl`, métodos, traits con firmas/defaults y módulos anidados indentados. La raíz `.ox` resuelve recursivamente módulos por rutas convencionales o `#[path]` relativo (`.ox`/`.rs`); exporta el árbol `.rs`, reescribe `#[path]` y conserva mapas por archivo. Pruebas CLI compilan y ejecutan ambas rutas. Las rutas fuera del proyecto y enlaces simbólicos finales se rechazan. La compilación Cargo del CRUD con Axum/Serde/Tokio requiere configurar sus dependencias en el proyecto |
| Expresiones, patrones y genéricos | Tokens Rust; parser Syn; `rustc` hace validación semántica | Parcial y con corpus E2E: genéricos/lifetime, bound `where`, `impl Fn`, closure, `Iterator::find` y patrones `Some`/`None` ejecutados en ambos modos; cobertura general pendiente |
| `match` | `coincidir expresión:` con brazos `patrón => expresión` o bloque indentado | Implementado en modo indentación, incluso como inicializador y con bloques de brazo; patrones/guardas/expresiones siguen Rust |
| Macros declarativas y DSL | Preservar definiciones e invocaciones Rust para Cargo/rustc; traducir solo aliases allowlisted | E2E ejecuta `macro_rules!`, una macro exportada local, `serde_json::json!` **1.0.154**, `tokio::select!` **1.54.1** y `paste::paste!` **1.0.15**. El DSL observado por la macro conserva identificadores, cadena, delimitadores anidados y `si`/`tipo`/`verdadero`; `paste!` genera `macro_si`, que se ejecuta. Casos limitados a esas entradas/versiones; no hay expansión en Óxido |
| Comentarios y formato | Los comentarios no se traducen; documentación se representa como atributos `doc` de Rust | Exportación/importación conservan comentarios fuera de grupos opacos; dentro de macros/atributos opacos se devuelve `OX4001`. `oxido formato` tiene regresiones CLI de idempotencia para ambos modos. El `.ox` mantiene el estilo de Óxido: en indentación normaliza sangría a cuatro espacios, espaciado de código normal y listas largas en `()`/`[]` a 100 columnas; preserva comentarios, literales y DSLs opacas. Cinco fixtures verifican la salida `.ox`, idempotencia, compilación de ambos exports y ejecución de uno; además comprueban que el Rust emitido coincide byte por byte con `rustfmt` 1.99.1. La cobertura estructural está cruzada en [testing.md](testing.md); esto no afirma compatibilidad universal con toda expresión Rust delegada a Syn. |
| Identificadores reservados y escape | `r#nombre` fuerza identificador; colisiones de alias reciben `OX3001` cuando corresponda | Parcial: sugerencia comprobada en funciones, parámetros, patrones anidados, bindings y `para`; contextos Rust adicionales siguen pendientes |
| Macros procedurales | Cargo/rustc pueden ejecutarlas; Óxido conserva invocaciones Rust pero no las analiza ni expande | E2E offline con `serde`/`serde_derive` **1.0.229** compila `Serialize`/`Deserialize` y `#[serde(rename = ...)]`; Tokio **1.54.1** ejecuta `#[tokio::main(flavor = "current_thread")]`; `paste` **1.0.15** recibe `[<macro_ si>]`, genera `macro_si` y ese código se ejecuta. Se compara la salida de `oxido ejecutar` con Cargo sobre una copia del árbol exportado fuera del proyecto original. Versiones concretas, no compatibilidad general |
| Dependencias Cargo | Requisito SemVer de crates.io; `path` solo con política explícita; lockfile persistente; compile/run locked y offline | E2E con `itoa`, `futures-executor`, `serde`, `serde_json` y `tokio` vendorizados, `CARGO_HOME` aislado, checksum y ejecución. La vista previa muestra lock/packages y no persiste; `--confirmar` ejecuta solo `cargo fetch`. `path` requiere `--permitir-rutas-locales`; `git`/URL rechazados. `compilar`/`ejecutar` requieren `--confiar-dependencias`; build script y macro procedural se prueban solo tras confianza. Alterar vendor o checksum falla en Cargo. Exportación repetida desde dos directorios produce el mismo `.rs` y no incluye rutas absolutas. Ver [ADR 0006](adr/0006-descarga-y-confianza-de-dependencias.md) y [procedencia del vendor](../tests/fixtures/cargo-registry/README.md) |
| `Result`, `Option`, `?` | Tipos estándar Rust, con aliases `Resultado`/`Opcion` y variantes incluidas en prelude | Alias de prelude inicial y operador `?` probados mediante generación; las rutas externas siguen siendo Rust |
| Colecciones estándar | `Vector`/`Cadena`, métodos comunes y módulos `std` con aliases documentados | Alias comprobados en generación; ejemplo e2e compila y ejecuta `Vector<Cadena>`, `agregar`, `largo` y macros |
| `async`/`await` y concurrencia | Generar Rust async equivalente; el proyecto elige un runtime compatible | E2E ejecuta una función con `.await` mediante `futures-executor`, además de `std::thread::spawn`; no existe runtime Óxido propio |
| Edición Rust y dependencias | Objetivo Rust 2024; crates.io por defecto; fuentes locales requieren autorización CLI | El workspace requiere Rust 1.99.1 y usa edición 2024. Cargo.lock se planifica y se persiste tras confirmación; `compilar`/`ejecutar` usan `--locked --offline` y requieren confianza explícita si hay dependencias. Git/URL no admitidos. El corpus E2E es `itoa`, `futures-executor`, fixture local con macro declarativa y fixtures locales `build.rs`/proc-macro. No se afirma compatibilidad general ni sandbox |
| `unsafe` | Conservar semántica Rust; auditoría y rechazo solo bajo opción explícita | Auditoría estática detecta las formas documentadas y `--rechazar` es opcional; la compilación de código de usuario conserva la semántica de Rust. El análisis no ve llamadas indirectas ni expansiones |
| LSP/editor | VS Code inicia el LSP Rust y el LSP comparte lexer/parser; no ejecuta Cargo automáticamente | Parcial, Fase 11 en curso: extensión con asociación `.ox`, configuración `oxido.serverPath`, reinicio y Workspace Trust `limited`. El protocolo usa parseo compartido, diagnósticos asíncronos lexer/parser y semantic tokens UTF-16. El índice local resuelve funciones, métodos, tipos y módulos con cualificadores, la declaración del módulo, referencias desde la declaración hacia llamadas cualificadas en otros archivos, y ante nombres repetidos ambiguos devuelve varias candidatas en lugar de elegir una. En workspace confiable hay worker persistente de `rust-analyzer` para hover, completado, inlay hints y navegación sobre un árbol Rust generado de módulos `.ox`; las ubicaciones mapeadas vuelven al URI/rango fuente. Tiene presupuesto de respuesta y fallback local, también ante errores transitorios del analizador; la prueba host exige el tipo `i32` de una variable local y una firma `pub fn saludo()` entre módulos. No se afirma mapeo semántico universal. `textDocument/formatting` indentado usa el mismo formateador que `oxido formato`, probado en host con texto canónico exacto. `Óxido: Comprobar con Cargo` exige confianza explícita y se prueba en host con una dependencia `itoa` vendorizada, `Cargo.lock` intacto y `E0308` mapeado a `util_error.ox`; Restricted Mode se prueba en un perfil nuevo con un `cargo` falso que no se invoca. La comprobación corre en un worker con una sola solicitud concurrente: `oxido/stats` responde mientras Cargo trabaja y `$/cancelRequest` mata el árbol de procesos; la prueba host exige `-32800` y la ausencia del marcador de finalización. `OXIDO_CARGO_BINARY` permite al operador anular el binario Cargo desde el entorno, no desde el workspace. La memoria residente se informa solo en Linux y se declara no disponible en Windows/macOS. El VSIX 0.1.0 se empaqueta con vsce 3.9.2 e instala en un perfil limpio; la prueba host exige activación desde el directorio de extensiones instaladas, ausencia de pruebas/perfiles en el paquete y `OX1002` desde `oxido-lsp`. El VSIX no incluye ni firma el binario LSP, que debe estar en `PATH` o configurarse en `oxido.serverPath`; faltan publicación y validaciones semánticas más amplias. Ver [Fase 11](fase-11-vscode-lsp.md) y [ADR 0010](adr/0010-frontera-lsp-y-confianza-editor.md) |
| Items Rust no listados | Braces: passthrough si Syn y rustc aceptan; indentation: rechazo salvo transformador estructural definido | En modo llaves se conservan items Rust passthrough; la importación de árboles conserva `mod` y otros items no funcionales. No se afirma soporte estructural indentado para items no enumerados |
| Tipos/métodos españoles | Prelude inicial enumerado en [aliases](aliases.md); métodos declarados localmente tienen prioridad sobre aliases | Aliases probados; `OX3002` advierte colisiones en el archivo `.ox` compilado. Otros archivos `.ox` aún no forman una unidad de compilación |
| Mensajes rustc en español | Traducción por código de diagnóstico JSON | Conjunto inicial de códigos; mensajes desconocidos conservan texto original y todos preservan código/span |
| Sistema de tipos/runtime propios | No existen | Fuera de alcance; `async` usa el runtime elegido por cada proyecto |

“Parcial” significa que existe evidencia para un subconjunto, no que cualquier programa de esa categoría funcione. Las limitaciones registradas no son restricciones permanentes del lenguaje. Syn valida sintaxis; Cargo/rustc comprueba tipos y compilación. `importar-proyecto <directorio-rust> --salida <directorio-oxido>` recorre `.rs` y `.ox`, convierte el subconjunto reversible, conserva los demás items Rust como passthrough y reescribe `#[path]` relativo entre extensiones cuando el destino existe dentro del árbol. Hay regresiones CLI para árboles mixtos, compilación/ejecución, rutas que escapan y destino simbólico; no implica compatibilidad universal con árboles Cargo arbitrarios. Los comentarios dentro de macros/atributos opacos se rechazan. Las verificaciones `--locked --offline` demuestran reproducibilidad solo porque las dependencias están disponibles localmente; no demuestran descarga sin red. El formateador indentado tiene salidas `.ox` esperadas y un cruce de las producciones estructurales admitidas; en esos fixtures el Rust emitido coincide byte por byte con `rustfmt` 1.99.1. Las variantes de expresiones, tipos, patrones y DSL de Rust que Syn acepta no se enumeran exhaustivamente. La salida JSON versionada se ofrece para `compilar`, `ejecutar` y `probar`; no se generaliza a todos los comandos.
