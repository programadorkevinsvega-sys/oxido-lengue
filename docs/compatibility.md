# Compatibilidad de Óxido 0.1 con Rust

Esta matriz describe el **alcance verificado**, no compatibilidad general con Rust ni un techo permanente del lenguaje. El objetivo es interoperar con bibliotecas Rust sin modificar su fuente, según el [contrato de interoperabilidad](compiler-pipeline.md#contrato-de-interoperabilidad-con-rust). Rust 2024 es la edición objetivo. La aceptación exige pruebas de fidelidad, casos positivos/negativos y compilación con Cargo/rustc cuando aplique; las brechas de interoperabilidad enumeradas aquí deben cerrarse con pruebas. La infraestructura transversal de pruebas y reportes está descrita en [testing](testing.md).

| Área | Decisión 0.1 | Estado actual del repositorio |
|---|---|---|
| Funciones libres | Estructura bilingüe en ambos modos; firma preservada como Rust | Parcial: generación y roundtrip de funciones; Cargo/rustc verificado con Hola, mundo |
| Variables y tipos | `dejar`; `mutable` equivale a `mut`; anotación local opcional | Inferencia local estática delegada en rustc y probada E2E; parámetros y firmas siguen las reglas de tipos de Rust. No hay inferencia propia |
| Bloques | `:`+indent o `{}` según modo, nunca mezclados como bloques | Los dos modos se generan; pruebas comparan semántica de bloques y expresiones finales |
| Valor del bloque | Última expresión sin `;` retorna valor; con `;` devuelve `()` | Regla preservada y probada para funciones, controles y métodos |
| `if/else`, `loop`, `while`, `for` | Keywords bilingües y bloques en ambos modos | Verificado para el corpus de funciones y controles; la semántica de expresiones sigue delegada en Rust |
| Tipos, referencias y borrowing | Sintaxis Rust preservada y parseada; semántica a `rustc` | Implementado para tipos y referencias Rust del corpus de funciones; préstamo probado end-to-end |
| Tuplas, arrays y tipos primitivos | Sintaxis Rust preservada; semántica a `rustc` | Implementado y probado en código ejecutado |
| `struct`, `enum`, `impl`, `trait`, `mod`, `use` | Items con sintaxis Rust o estructura indentada documentada | `struct`/`enum`/`use` admiten estructura indentada; `impl`, métodos, traits con firmas/defaults y módulos anidados también se admiten indentados. La raíz `.ox` resuelve recursivamente módulos por rutas convencionales o `#[path]` relativo (`.ox`/`.rs`); exporta el árbol `.rs`, reescribe `#[path]` y conserva mapas por archivo. Pruebas CLI compilan y ejecutan ambas rutas. Las rutas fuera del proyecto y enlaces simbólicos finales se rechazan. La compilación Cargo del CRUD con Axum/Serde/Tokio requiere configurar sus dependencias en el proyecto |
| Expresiones, patrones y genéricos | Tokens Rust; parser Syn; `rustc` hace validación semántica | Parcial y con corpus E2E: genéricos/lifetime, bound `where`, `impl Fn`, closure, `Iterator::find` y patrones `Some`/`None` ejecutados en ambos modos; cobertura general pendiente |
| `match` | `coincidir expresión:` con brazos `patrón => expresión` o bloque indentado | Implementado en modo indentación, incluso como inicializador y con bloques de brazo; patrones/guardas/expresiones siguen Rust |
| Macros declarativas y DSL | Preservar definiciones e invocaciones Rust para Cargo/rustc; traducir solo aliases allowlisted | E2E ejecuta `macro_rules!`, una macro exportada local, `serde_json::json!` **1.0.154**, `tokio::select!` **1.54.1** y `paste::paste!` **1.0.15**. El DSL observado por la macro conserva identificadores, cadena, delimitadores anidados y `si`/`tipo`/`verdadero`; `paste!` genera `macro_si`, que se ejecuta. Casos limitados a esas entradas/versiones; no hay expansión en Óxido |
| Comentarios y formato | Los comentarios no se traducen; documentación se representa como atributos `doc` de Rust | Exportación/importación conservan comentarios fuera de grupos opacos; dentro de macros/atributos opacos se devuelve `OX4001`. `oxido formato` tiene regresiones CLI de idempotencia para ambos modos. El `.ox` mantiene el estilo de Óxido: en indentación normaliza sangría a cuatro espacios, espaciado de código normal y listas largas en `()`/`[]` a 100 columnas; preserva comentarios, literales y DSLs opacas. Cinco fixtures verifican la salida `.ox`, idempotencia, compilación de ambos exports y ejecución de uno; además comprueban que el Rust emitido coincide byte por byte con `rustfmt` 1.99.1. La cobertura estructural está cruzada en [testing.md](testing.md); esto no afirma compatibilidad universal con toda expresión Rust delegada a Syn. |
| Identificadores reservados y escape | `r#nombre` fuerza identificador; colisiones de alias reciben `OX3001` cuando corresponda | Parcial: sugerencia comprobada en funciones, parámetros, patrones anidados, bindings y `para`; contextos Rust adicionales siguen pendientes |
| Macros procedurales | Cargo/rustc pueden ejecutarlas; Óxido conserva invocaciones Rust pero no las analiza ni expande | E2E offline con `serde`/`serde_derive` **1.0.229** compila `Serialize`/`Deserialize` y `#[serde(rename = ...)]`; Tokio **1.54.1** ejecuta `#[tokio::main(flavor = "current_thread")]`; `paste` **1.0.15** recibe `[<macro_ si>]`, genera `macro_si` y ese código se ejecuta. Se compara la salida de `oxido ejecutar` con Cargo sobre una copia del árbol exportado fuera del proyecto original. Versiones concretas, no compatibilidad general |
| Dependencias Cargo | Requisito SemVer de crates.io; `path` solo con política explícita; lockfile persistente; build/check/run locked y offline | E2E con `itoa`, `futures-executor`, `serde`, `serde_json` y `tokio` vendorizados, `CARGO_HOME` aislado, checksum y ejecución. El proyecto Cargo generado está en `target/oxido/`, incluye fuentes `.ox` como `src/main.ox` y `src/dominio/mod.ox`, junto a Rust generado; Cargo conserva sus artefactos en `target/oxido/target/{debug,release}`. `check` usa `cargo check`; `build`/`compilar` usa `cargo build`; `run`/`ejecutar` delega en Cargo. La vista previa de dependencias muestra lock/packages y no persiste; `--confirmar` ejecuta solo `cargo fetch`. `path` requiere `--permitir-rutas-locales`; `git`/URL rechazados. Las acciones que compilan dependencias requieren `--confiar-dependencias`; build script y macro procedural se prueban solo tras confianza. Alterar vendor o checksum falla en Cargo. Exportación repetida desde dos directorios produce el mismo `.rs` y no incluye rutas absolutas. Ver la [procedencia del vendor](../tests/fixtures/cargo-registry/README.md) |
| `Result`, `Option`, `?` | Tipos estándar Rust, con aliases `Resultado`/`Opcion` y variantes incluidas en prelude | Alias de prelude inicial y operador `?` probados mediante generación; las rutas externas siguen siendo Rust |
| Colecciones estándar | `Vector`/`Cadena`, métodos comunes y módulos `std` con aliases documentados | Alias comprobados en generación; ejemplo e2e compila y ejecuta `Vector<Cadena>`, `agregar`, `largo` y macros |
| `async`/`await` y concurrencia | Generar Rust async equivalente; el proyecto elige un runtime compatible | E2E ejecuta una función con `.await` mediante `futures-executor`, además de `std::thread::spawn`; no existe runtime Óxido propio |
| Edición Rust y dependencias | Objetivo Rust 2024; crates.io por defecto; fuentes locales requieren autorización CLI | El workspace requiere Rust 1.99.1 y usa edición 2024. Cargo.lock se planifica y se persiste tras confirmación; `check`/`build`/`run` usan `--locked --offline` y requieren confianza explícita si hay dependencias. Git/URL no admitidos. El corpus E2E es `itoa`, `futures-executor`, fixture local con macro declarativa y fixtures locales `build.rs`/proc-macro. No se afirma compatibilidad general ni sandbox |
| `unsafe` | Conservar semántica Rust; auditoría y rechazo solo bajo opción explícita | Auditoría estática detecta las formas documentadas y `--rechazar` es opcional; la compilación de código de usuario conserva la semántica de Rust. El análisis no ve llamadas indirectas ni expansiones |
| LSP/editor | VS Code y `oxido-lsp` | Implementado parcialmente; la extensión, pruebas, capacidades semánticas, confianza, distribución y límites están descritos en la [guía de VS Code y LSP](vscode.md) |
| Items Rust no listados | Braces: passthrough si Syn y rustc aceptan; indentation: rechazo salvo transformador estructural definido | En modo llaves se conservan items Rust passthrough; la importación de árboles conserva `mod` y otros items no funcionales, y mantiene los `.rs` convertidos en `.oxido/original/`. El passthrough de funciones es selectivo: `const`/`unsafe`/`extern fn`, atributos con ruta o argumentos y `let` con patrón slice. Las macros externas con ruta mantienen sus grupos de argumentos opacos; la declaración de función alrededor se traduce cuando la validación de ida y vuelta confirma equivalencia. Los atributos simples y las macros del prelude siguen el AST estructural. No se afirma soporte estructural indentado para items no enumerados |
| Tipos/métodos españoles | Prelude inicial enumerado en [aliases](aliases.md); métodos declarados localmente tienen prioridad sobre aliases | Aliases probados; `OX3002` advierte colisiones en el archivo `.ox` compilado. Otros archivos `.ox` aún no forman una unidad de compilación |
| Mensajes `rustc` en español | Traducción parcial de resúmenes por código en diagnósticos JSON | Doce códigos tienen traducción de resumen; el código y los detalles disponibles se conservan, los códigos desconocidos mantienen el mensaje original y no hay selector de idioma. Ver [diagnósticos y posiciones](diagnostics.md) |
| Sistema de tipos/runtime propios | No existen | Fuera de alcance; `async` usa el runtime elegido por cada proyecto |

“Parcial” significa que existe evidencia para un subconjunto, no que cualquier programa de esa categoría funcione. Las limitaciones registradas no son restricciones permanentes del lenguaje. Syn valida sintaxis; Cargo/rustc comprueba tipos y compilación. `importar-proyecto <directorio-rust> --salida <directorio-oxido>` recorre `.rs` y `.ox`, conserva cada archivo e importa por defecto cada `.rs` tal cual: solo antepone `sintaxis llaves`, sin cambiar `fn` ni el formato. Guarda los originales en `.oxido/original/`, conserva los items Rust no convertidos como passthrough y reescribe `#[path]` relativo entre extensiones cuando el destino existe dentro del árbol. Con `--espanol` se activa la conversión reversible (`fn` → `funcion`) y su validación de ida y vuelta; el manifiesto distingue `verbatim-rust`, `translated-oxido` y `passthrough-rust`. Un `#[path]` que escapa de la raíz o apunta a una fuente inexistente es fatal; un Rust inválido o no convertible se preserva como passthrough. La validación de ida y vuelta canoniza ambos lados con `prettyplease` y `rustfmt`, por lo que llaves o puntos y coma redundantes no se declaran pérdida. Hay regresiones CLI para árboles mixtos, compilación/ejecución, rutas que escapan y destino simbólico; no implica compatibilidad universal con árboles Cargo arbitrarios. Los comentarios dentro de macros/atributos opacos se rechazan. Las verificaciones `--locked --offline` demuestran reproducibilidad solo porque las dependencias están disponibles localmente; no demuestran descarga sin red. El formateador indentado tiene salidas `.ox` esperadas y un cruce de las producciones estructurales admitidas; en esos fixtures el Rust emitido coincide byte por byte con `rustfmt` 1.99.1. Las variantes de expresiones, tipos, patrones y DSL de Rust que Syn acepta no se enumeran exhaustivamente. La salida JSON estructurada se admite en los comandos Cargo sobre un target de paquete único; los workspaces importados reportan texto y no tienen salida JSON estructurada todavía.

La importación de un workspace Cargo convierte cada `Cargo.toml` en un `oxido.toml` con su manifiesto Cargo preservado como datos bajo `[cargo.manifest]`; no copia archivos `Cargo.toml`. `Cargo.lock` se conserva. `oxido check`, `oxido build`, `oxido run` y `oxido test` (también `verificar`, `compilar`, `ejecutar` y `probar`) reconocen el manifiesto de importación y reconstruyen los paquetes en staging temporal. `check` valida todo el workspace; `build` genera los binarios del workspace en `target/oxido/{debug,release}` sin ejecutarlos; `run` elige el binario/ejemplo asociado al `.ox` y lo ejecuta; `test` compila y ejecuta las pruebas. Cargo usa `--locked --offline`. Los miembros admiten patrones glob de Cargo (probado con `*`) y respetan `workspace.exclude`. Se exportan targets de biblioteca, binarios, build scripts, ejemplos, pruebas y benches, tanto convencionales como declarados con rutas/nombres personalizados. La operación no modifica los archivos importados fuera de `target/oxido` y elimina el staging al finalizar. Los diagnósticos JSON de rustc usan mapas por archivo generado y ubican errores de módulos `.ox` en su archivo/línea/columna fuente; diagnósticos de Rust passthrough sin mapa mantienen el archivo generado o se presentan como diagnósticos externos. La regresión CLI ejecuta un workspace con miembros glob, dependencia local, binario y ejemplo personalizados, prueba de integración y bench, y verifica un error de tipos dentro de un módulo `.ox`. Las dependencias deben estar previamente disponibles localmente; las acciones que compilan requieren `--confiar-dependencias` porque Cargo puede ejecutar `build.rs` y macros procedurales.
