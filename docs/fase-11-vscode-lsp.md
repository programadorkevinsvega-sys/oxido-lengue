# Fase 11 — VS Code y LSP

**Estado:** completada en su alcance técnico; la Fase 11.1 añade ámbitos locales acotados, `prepareRename`/`rename` e índice incremental persistente según [ADR 0012](adr/0012-ambitos-locales-rename-e-indice-persistente.md). La extensión asocia `.ox`; el LSP comparte lexer/parser, entrega semantic tokens, hover, completado, símbolos, definición y referencias locales, y calcula diagnósticos de edición en un worker separado. El índice local de declaraciones cubre funciones, métodos, estructuras, enumeraciones, rasgos, alias de tipo y módulos; resuelve cualificadores como `dominio::modelos::Alumno::nuevo`, distingue nombres repetidos en módulos distintos, resuelve la declaración del módulo y devuelve todas las ubicaciones candidatas cuando no puede desambiguar. Los semantic tokens clasifican declaraciones, referencias y ámbitos locales de los documentos abiertos con ese índice, cubren también archivos cerrados mediante la caché persistente y, en workspace confiable, fusionan los tokens de `rust-analyzer` que tengan correspondencia token a token exacta; lo que no se resuelve conserva el fallback léxico. Los resultados viejos se cancelan y descartan al cambiar o cerrar el documento. El servidor limita 64 documentos, 4 MiB por documento, 16 MiB de texto abierto, cuatro cálculos concurrentes de semantic tokens, una comprobación Cargo y una tarea de diagnóstico en cola. `oxido/check` se ejecuta en un worker: el bucle sigue respondiendo `oxido/stats` y otras solicitudes, y `$/cancelRequest` marca la solicitud y mata el árbol de procesos de Cargo; una prueba host lo verifica con un Cargo controlado que tarda y deja marcadores de inicio y fin. El editor dispone de `Óxido: Ver estadísticas del editor`, que muestra documentos, bytes, rondas de diagnóstico, duración del último diagnóstico, memoria residente en Linux y tiempo de ida y vuelta; en Windows y macOS la memoria se informa como no disponible, sin inventar una métrica. El índice incremental vive en la caché del usuario, fuera del workspace, con versión de esquema, invalidación por fecha/tamaño/hash, límites y escritura atómica. En un workspace confiable, un worker persistente consulta `rust-analyzer` sobre un árbol Rust temporal resuelto desde los módulos `.ox`; las ubicaciones devueltas para archivos mapeados vuelven al URI y rango del `.ox` de origen. `prepareRename` y `rename` se delegan en ese mismo worker y solo se aplican si todas las URI y rangos del `WorkspaceEdit` tienen correspondencia exacta con el `.ox`; en caso contrario se rechaza el edit completo y se intenta el fallback local conservador. Si el analizador devuelve un error transitorio o una navegación vacía, la consulta conserva el resultado local acotado en vez de propagar el vacío. Sus solicitudes y las del propio analizador se acotan para no bloquear el bucle LSP. `textDocument/formatting` de modo indentado usa el mismo formateador que `oxido formato`, extraído a `oxido-compiler`; la prueba host exige el texto canónico exacto. La matriz Windows/macOS, la firma, la notarización, la publicación, el SBOM, los builds reproducibles y los benchmarks de latencia/memoria fuera de Linux pasan a Fase 12 según [ADR 0011](adr/0011-cierre-fase-11-y-distribucion.md).

La decisión de seguridad está en [ADR 0010](adr/0010-frontera-lsp-y-confianza-editor.md) y la extensión 11.1 en [ADR 0012](adr/0012-ambitos-locales-rename-e-indice-persistente.md). El servidor LSP no inicia Cargo ni `rust-analyzer` al abrir o editar; `Óxido: Comprobar con Cargo` es una acción separada que exige confianza y usa el `oxido.toml` validado del proyecto. Leer `oxido.toml` no ejecuta código. La extensión declara soporte `limited` para Workspace Trust y restringe la configuración `oxido.serverPath` en Restricted Mode. En Restricted Mode el renombrado usa el índice y los ámbitos locales, sin consultar `rust-analyzer`.

## Evidencia de Fase 11.1: ámbitos, renombrado e índice

- `crates/oxido-rust-backend` emite correspondencias token a token además de las de fragmento. `maps_individual_fragment_tokens_for_precise_rename_ranges` demuestra que un rango de renombrado puede mapear solo el identificador. - `crates/oxido-lsp/src/lib.rs` añade `prepareRename`/`rename` a las capacidades. Las pruebas `rename_local_binding_only_edits_its_lexical_scope`, `rename_local_binding_skips_shadowed_and_qualified_names`, `rename_rejects_ambiguous_cross_file_symbols`, `rename_rejects_a_reserved_new_name` y `semantic_tokens_use_symbols_from_closed_workspace_files` fijan el fallback, el rechazo y la exclusión de sombreados o rutas cualificadas. `cargo test -p oxido-lsp --offline` ejecuta 61 pruebas.

Abre un `.ox`, recibe el diagnóstico `OX1002` real y solicita hover, estadísticas, completado, inlay hints, definición y semantic tokens a través del cliente LSP real; además verifica que `util::saludo()` navega a `util.ox` y exige tipos concretos en `semantic_tokens.ox`. La prueba exige al menos una respuesta real de `rust-analyzer`, no solo el fallback local. CI instala explícitamente el componente `rust-analyzer` del toolchain fijado (`components: rust-analyzer`) porque el proxy de `rustup` puede existir sin el componente; las pruebas de integración se omiten únicamente cuando `rust-analyzer --version` no responde con éxito. El caso Cargo ejecuta una compilación real, el caso de navegación/formato demuestra el índice local, el formateador compartido, el completado, los inlay hints y los símbolos sin confianza, y añade edición incremental, documento incompleto y tres solicitudes concurrentes de tokens; el caso confiable exige además `prepareRename`/`rename` mapeados y la caché del índice fuera del workspace, el caso de cancelación demuestra que el bucle responde durante Cargo y mata el proceso, los casos VSIX empaquetan, instalan y activan la extensión desde un perfil limpio (uno con el servidor incluido y otro sin él), y el caso restringido demuestra que no se inicia Cargo y que el renombrado local funciona sin `rust-analyzer`. `OXIDO_HOST_ONLY=cargo` permite repetir un caso durante el desarrollo; también se aceptan `trusted`, `navigation`, `cancellation`, `installed`, `bundled` y `restricted`.

La suite host sí ejecuta VS Code, el bridge disponible de `rust-analyzer` y Cargo; las pruebas de protocolo y manifiesto no sustituyen pruebas de Cargo, mapeo semántico completo ni otras funciones pendientes del editor. La compilación Cargo del host usa una dependencia vendorizada concreta; no demuestra descarga desde crates.io ni compatibilidad general de dependencias. El renombrado delegado solo cubre regiones con correspondencia token a token y el fallback local es conservador; no se presenta como refactorización universal. La caché del índice se probó en Linux y no se ha ejecutado en Windows/macOS. La matriz Windows/macOS, la firma, la notarización, la publicación y los benchmarks multiplataforma no forman parte de la evidencia local de Fase 11/11.1; se ejecutan en Fase 12.

## Instalación de desarrollo

1. Compila el servidor: `cargo build --release -p oxido-lsp`.
2. Asegúrate de que `oxido-lsp` esté en `PATH` o configura `oxido.serverPath` en ajustes de usuario.
3. Abre `editors/vscode-oxido` como proyecto de extensión con Extension Development Host, o empaqueta e instala el VSIX local:

   ```sh
   npm --prefix editors/vscode-oxido run package:vsix
   code --install-extension editors/vscode-oxido/dist/oxido-language-support-0.1.0.vsix
   ```

   El VSIX estándar no incluye `oxido-lsp`; el paso 2 sigue siendo necesario. Para producir un paquete que incluya el servidor de la plataforma actual:

   ```sh
   OXIDO_SERVER_BINARY=target/release/oxido-lsp \
   OXIDO_VSIX_TARGET=linux-x64 \
   npm --prefix editors/vscode-oxido run package:vsix:server
   code --install-extension editors/vscode-oxido/dist/oxido-language-support-0.1.0-linux-x64.vsix
   ```

   En ese paquete el binario vive en `server/` y se usa cuando `oxido.serverPath` conserva el valor por defecto; una ruta configurada explícitamente sigue teniendo prioridad. Ningún paquete está firmado ni se distribuye desde un marketplace. El workflow de release prepara la matriz de plataformas, pero solo Linux x64 se ha ejecutado localmente; la ejecución real de la matriz, la firma, la notarización y la publicación se cierran en Fase 12.
4. Abre un proyecto `.ox` con `oxido.toml` válido o un archivo con cabecera `sintaxis indentacion`/`sintaxis llaves`.

La configuración leída desde el workspace solo selecciona el modo y está limitada por el parser de configuración; no contiene comandos. El análisis al editar es local. El comando Cargo requiere confianza explícita y usa `--locked --offline`; no habilita dependencias de usuario desde el LSP en este corte.
